# Pervagans Web App — Responsive / Mobile Audit Report

## 1. Executive Summary

Pervagans is a desktop-first React/Next.js app whose responsive layer was bolted on via a handful of `@media` queries rather than designed mobile-first. The audit covering 118 verified findings across **9 surfaces** (chat dashboard, feature/space pages, spaces index, MCP catalog, gallery, settings, admin, billing, auth, and shared modal/canvas/skill-picker components) shows the app is **functional but structurally fragile on phones**: the primary input control can hide behind browser chrome, several popovers and tables overflow the viewport, key actions are hover-only and therefore unreachable by touch, and dozens of tap targets fall under the 44px minimum.

The defects are not random — they cluster into a small number of **systemic root causes**, each repeated verbatim across many files. Fixing the root cause once (often a 1-3 line CSS change applied app-wide) clears whole families of findings.

### Systemic themes (root causes, ranked by impact)

1. **`100vh` everywhere, `dvh` nowhere — mobile browser chrome clips the docked composer.** The single highest-impact defect. `.shell`, `.main`, and `.stage[data-chat]` all hard-lock to `height:100vh`; on iOS Safari / Chrome Android the dynamic toolbar makes the visible viewport shorter than `100vh`, pushing the composer (the send button — the *primary action*) under the browser UI. A repo-wide grep returns **zero** `dvh`/`svh`/`lvh` matches. Repeated on the feature, space, settings, admin, mcps, auth, and billing shells.

2. **`viewportFit:"cover"` is set, but ZERO `env(safe-area-inset-*)` exists.** This is the exact spec-warned bad pairing: `layout.tsx:94` opts the layout edge-to-edge under the notch/home-indicator, yet not one rule compensates. The docked composers, two fixed hamburgers, drawer footers, full-screen modals, and the canvas drawer all collide with the notch or gesture bar.

3. **Fixed `min-width:320px` / `min-width:280px` popovers with no phone cap.** The dashboard `.model-pop` / `.popover`, the feature `.feat-model-pop`, and the account sub-popover (`.acct-sub-pop`) all exceed the ~272px composer width on a 320px phone and overflow the opposite edge, clipping their rows. Phone caps exist only as `.feat-composer`-scoped descendant rules that never match the bare dashboard classes.

4. **Hover-only affordances with no `@media (hover:none)` / `pointer:coarse` fallback.** Code-block Copy / Open-in-Canvas, history-row Rename/Delete menus, feature-chat overflow menus, and gallery prompt tooltips are all `opacity:0` until `:hover`. There is **no** coarse-pointer fallback anywhere except one unrelated `spaces.css` block. On touch these controls are invisible and unreachable — several are the *only* path to a core action (copy code, rename/delete a chat).

5. **Sub-44px touch targets — the file's own WCAG comment is unmet.** A `@media (max-width:768px)` block claims to enforce 44px but enumerates only icon-chrome buttons; the actual tappable rows (nav, feature, history, settings, spaces, skill, media-controls, canvas, table, billing/task buttons) are excluded and stay ~20-40px tall.

6. **Missing phone breakpoint tiers + breakpoint mismatches.** Several surfaces (spaces, mcps, settings, admin, auth, billing, gallery) have no `<=480px` tier, so a 768px tablet and a 320px phone render identically (fixed 24-32px gutters, 44px headings). Separately, the app shell drawers activate at `<=880px` while feature/admin adaptations fire at `<=820px`/`<=640px`, leaving 40-60px dead bands where a fixed sidebar/table collides with the floating hamburger.

7. **Flex items without `min-width:0` / `overflow-wrap` — long tokens & tables overflow.** Admin tables (`nowrap` on every cell), task cards, run-step rows, inline `<code>`, the connect button, and auth emails can't shrink below intrinsic width, causing clip or horizontal scroll. RTL mirrors every popover/table/anchor overflow to the opposite edge.

**Overall health:** No surface is fully broken, but the chat surface — the product's core — has a critical `100vh` defect that can hide the send button, and touch users lose entire features (copy code, rename/delete chats) to hover-only affordances. The good news: ~70% of findings collapse into the 7 themes above, and the top 3 are fixable with a global `dvh` migration, a global safe-area pass, and one shared popover cap.

## 3. Per-Theme Breakdown (root cause → one systemic fix)

### Theme A — `100vh` instead of `dvh` (mobile chrome clips the docked/sticky composer)
**Affected:** `dashboard.css:25,294,437` (critical, chat) • `feature.css:25` • `settings.css:8` • `admin.css:2` • `mcps.css:2` • `auth.css:2` • `billing/page.tsx:122`, `billing/return/page.tsx:19`, `billing/cancel/page.tsx:7` • feature/space composers are `position:sticky;bottom:0` (`feature.css:668-677`) anchored to the bottom of these `100vh` columns.
**Root cause:** Static `vh` resolves to the *largest* viewport (chrome retracted); the visible area is ~80-100px shorter when the toolbar shows, so the bottom-docked composer/cards fall below the fold. Grep confirms zero `dvh`/`svh`/`lvh` in the repo.
**One systemic fix:** Replace every load-bearing `height:100vh` / `min-height:100vh` with a two-line declaration: `height:100vh; height:100dvh;` (fallback first). For the `min-height` shells (settings/admin/mcps/auth/feature) `min-height:100dvh` is sufficient (these are floors → low severity, content not clipped, only the chat `height:100vh` is the hard clip).

### Theme B — `viewportFit:"cover"` with no `env(safe-area-inset-*)`
**Affected:** `layout.tsx:94` (the opt-in) • composer bottoms (`dashboard.css:469`, `feature.css:699`) • two fixed hamburgers (`dashboard.css:1059-1061`, `feature.css:860-861`) • sidebar/sub-sidebar drawers + `.sb-foot` (`dashboard.css:1095`, `feature.css:902`) • full-screen modals (`dashboard.css:1136`, `feature.css:225`) • canvas drawer (`dashboard.css:932-938,954`) • auth shell (`auth.css:5`) • task/billing inline paddings.
**Root cause:** `cover` extends content under the notch/rounded-corner/home-indicator; with no inset compensation the OS genuinely draws controls in the unsafe zone (active, not theoretical — the precondition is met).
**One systemic fix:** Add safe-area insets to every fixed/edge element: composers `margin/padding-bottom: max(24px, env(safe-area-inset-bottom))`; hamburgers `top: max(14px, env(safe-area-inset-top))`, `inset-inline-start: max(14px, env(safe-area-inset-left))`; `.sb-foot`/drawer foot `padding-bottom: env(safe-area-inset-bottom)`; modal/canvas top+bottom insets. (Or drop `cover` if insets aren't wanted — simplest, but loses edge-to-edge.)

### Theme C — Fixed-width popovers overflow the phone composer/viewport
**Affected:** `dashboard.css:359 (.model-pop), 373 (.popover)` (min-width:320px) • `feature.css:681-689 (.feat-model-pop)` (min-width:280px, 561-768px band) • `Sidebar.tsx:674/671` + `dashboard.css:260,261` (`.acct-sub-pop` min-width:280px, ~60px off-screen). RTL mirrors all three.
**Root cause:** Fixed min-widths exceed the ~272px composer / narrow drawer; phone caps that exist are scoped to `.feat-composer` descendants and never reach the bare/dashboard/account classes.
**One systemic fix:** A shared phone cap for all composer/anchored popovers: `@media(max-width:560px){.popover,.model-pop,.feat-model-pop,.acct-sub-pop{min-width:0;width:min(320px,calc(100vw-24px));max-width:calc(100vw-24px)}}`, pin to a single inline edge with a gutter, and fix the JS `openSub` clamp constant (`220`→ measured width). Consider bottom sheets on phones. Also give `.model-pop`/`.popover` `max-height:min(70vh,520px);overflow-y:auto` so tall model lists scroll internally instead of escaping a short/landscape viewport.

### Theme D — Hover-only affordances with no touch fallback
**Affected:** `dashboard.css:920-928` (code-block Copy / Open-in-Canvas — high, core action) • `dashboard.css:1196,1200` (history Rename/Delete) • `feature.css:546-553` (feature-chat menu) • `gallery/page.tsx:85` + `dashboard.css:906` (prompt tooltip, low) • `SpaceChat.tsx:414` (mic button — `title`-only, dead on touch).
**Root cause:** `opacity:0` + `:hover` reveal with **no** `@media (hover:none)`/`pointer:coarse` rule anywhere (the only such block, `spaces.css:273`, targets unrelated selectors). Touch has no hover, so these are invisible/inert.
**One systemic fix:** A single global coarse-pointer block: `@media(hover:none){.md-code-actions .md-code-copy,.md-code-canvas,.sb-history-menu-btn,.feat-subsb-item-menu-btn{opacity:1}}`. For `title`-only controls (mic, gallery prompt) give an onClick/tap-to-reveal so info surfaces on tap, or hide until the feature ships.

### Theme E — Sub-44px touch targets excluded from the bump list
**Affected (the `<=768px` bump at `dashboard.css:1248-1263` covers only icon-chrome):** nav/feature/history rows (`dashboard.css:54,88-102,189-205`) • media controls `.mc-chip/.mc-neg/.mc-seed-input` 28px (`dashboard.css:840-866`) • `.feat-subsb-row`/`-row-button` ~30px (`feature.css:953`) • `.feat-file-del` 22px / `.feat-skill-del` 20px (`feature.css:282,214`) • `.gal-del` 26px (`dashboard.css:910`) • `.sp-new-btn` ~38px, `.sp-card-menu-item` ~34px, `.sp-menu-btn` 34px (`spaces.css:66,263,417`) • settings nav/Save ~40px (`settings.css:49,151`) • admin in-table buttons/selects/checkbox ~22-26px (`admin.css:105,96`, `page.tsx:161`) • canvas tabs/act/close 20-24px (`dashboard.css:945,948,950`) • task toggle buttons ~16px (`tasks/page.tsx:134,139`) • `.skp-item` ~40px (`skill-picker.css:61`).
**Root cause:** The mobile bump enumerates icon buttons; the actual tappable rows/controls were never added — the file's own WCAG 2.5.5 comment (`dashboard.css:1243`) is unmet.
**One systemic fix:** Expand the `@media(max-width:768px)` selector list to include the row/action classes with `min-height:44px` (rows) and `min-width:44px;min-height:44px` (icon/delete controls), and use `@media(hover:none)` for the spaces/admin/canvas ones. Bump inter-row `gap` from 1px (`dashboard.css:87/187`) to ≥4px to stop mis-taps. For media controls, also `min-width:40px` on chips.

### Theme F — Missing phone tiers & breakpoint mismatches
**Affected:** Spaces (`spaces.css` — only `1000px` collapse, no `<=480` tier → fixed 28-32px gutters, 44px/20px headings, no header wrap) • mcps (`mcps.css` — only one detail-page `@media`, shell `24px`/h1 `44px` unscaled) • settings (`settings.css` — 24px shell + 22px section unscaled, h1 44px) • admin (`admin.css` — single `640px` block; shell drawers at `880px` → 641-880px gap) • feature/shell mismatch (`820px` vs `880px` → 60px collision band) • gallery (`dashboard.css:886` — no `.gal-*` `@media`, single-column giant tiles) • auth (zero `@media`) • billing (inline styles, no media).
**Root cause:** One breakpoint (or none) does all the work; tablet and 320px phone render identically; shell/content breakpoints disagree.
**One systemic fix:** Add a consistent `@media(max-width:480px)` tier per surface that trims shell/section/card padding to ~14-16px, scales `h1` to `clamp(28px,8vw,44px)`/`~30px`, and enables header wrap; **align all drawer/grid breakpoints to `880px`** (feature grid + feature hamburger) and add an `880px`/`768px` admin tier. Mirror the existing `.mcps-shell` phone treatment (`dashboard.css:1152-1154`) onto settings/spaces/billing.

### Theme G — Flex items without `min-width:0` / `overflow-wrap`; long tokens & tables overflow
**Affected:** admin `nowrap` cells (`admin.css:82`) • task card title (`tasks/page.tsx:110`) + step rows (`:117-120`) • inline `.md-body code` (`dashboard.css:537`) • `.usage-card .model-name` (`settings.css:184`) • URL span in connector cards (`RemoteMcpSection.tsx:122`) • web-search chip bare text node (`SpaceChat.tsx:369` — no ellipsis) • auth email (Theme covered above). RTL mirrors.
**Root cause:** Flex items default to `min-width:auto` and can't shrink below intrinsic content; `overflow-wrap` is not inherited, so ancestor `word-wrap:break-word` doesn't reach inline `<code>` or bare text nodes.
**One systemic fix:** Add `min-width:0` to flex containers/items holding shrinkable text and `overflow-wrap:anywhere;word-break:break-word` to `.md-body code`, task title/step spans, and `.usage-card .model-name` (plus `overflow:hidden;text-overflow:ellipsis;white-space:nowrap`). Wrap bare-text-node chips (web-search label) in a `<span>` so existing ellipsis rules catch them. For tables, prefer wrapper `overflow-x:auto` (keep `<table>` as `display:table` — see Theme below) or a `<=480px` stacked-card layout.

### Theme H — Other cross-cutting structural nits
- **Drawer scroll not locked** (`features/[slug]/page.tsx:54-63`, `feature.css:874`): opening the sub-sidebar drawer doesn't set `body.modal-open`/`overflow:hidden` and the backdrop has no `overscroll-behavior` → background scroll-chains. Fix: lock body scroll on `subDrawerOpen` + `overscroll-behavior:contain` on `.feat-subsb`/backdrop.
- **No in-drawer close X** (`dashboard.css:1130`): `.sb-collapse{display:none}` in drawer mode; only backdrop/Esc/relocated-hamburger dismiss. Fix: show an explicit X in the drawer header on `<=880px`.
- **Half-converted table** (`admin.css:165`): `display:block` on `<table>` at `640px` is redundant (wrapper already scrolls) and risks column/sticky-header misalignment. Fix: keep scroll on `.admin-table-wrap`, drop `display:block` on the table.
- **Auto-grow textarea pixel cap** (`FeatureChat.tsx:144`, `SpaceChat.tsx:112`): 280px cap with no viewport relationship swallows short/landscape phones. Fix: `Math.min(ta.scrollHeight, Math.min(280, innerHeight*0.35))` or CSS `max-height:min(280px,35dvh)`.
- **Canvas backdrop non-dismissable at 100vw** (`CanvasDrawer.tsx:43,54`): the × is the *only* touch dismiss → must be bulletproof (depends on Theme B/C/E fixes).
- **Sticky header color seam** (`skill-picker.css:45`): `background:var(--bg)` ≠ modal `--panel-solid` → visible dark band. Fix: `background:var(--panel-solid)`.
- **Nested double-scroll** (`skill-picker.css:30` + `dashboard.css:1026`): two `overflow-y:auto` regions on a full-screen phone modal. Fix: one scroll surface (let `.modal-body` own it on phones).
- **`.control` stays `flex-end` after stacking** (`settings.css:97`): values/avatar hug the right edge under left-aligned labels. Fix: `@media(max-width:720px){.settings-row > .control{justify-content:flex-start}}`.
- **Connected pill unstyled in grid** (`RemoteMcpSection.tsx:121` vs `mcps.css:262`): descendant selector doesn't match `.mcp-card` → bare text crowds URL row. Fix: add `.mcp-card .connected-pill{...}`.

## 5. Recommended Fix Order

### Phase 1 — Quick wins (global, low-risk, highest leverage)
1. **`vh→dvh` migration (Theme A).** Add `height:100dvh`/`min-height:100dvh` (with `100vh` fallback) on `.shell`/`.main`/`.stage[data-chat]` and the 6 page shells. Clears the **critical** chat clip + 7 high/low shell findings in one pass.
